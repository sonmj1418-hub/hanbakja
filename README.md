# 한박자

YouTube Shorts를 열기 전에 한 박자 멈추고, 오늘 얼마나 봤는지에 따라 개입의 세기를 바꾸는 사용 조절 앱입니다.

캡스톤 계획서의 흐름인 **감지 → 이유 질문 → Level 1~3 개입 → 결과 기록 → 통계와 일일 리포트**를 쓸 수 있습니다. 안드로이드 앱은 접근성 서비스를 직접 켜면 YouTube Shorts와 Instagram Reels 화면에서 그 개입을 엽니다. 홈의 **쇼츠 열기**는 연습용 시뮬레이션입니다.

기록은 기기 안에만 남습니다. 화면의 글, 메시지, 비밀번호, 계정은 저장하거나 보내지 않습니다. 계정, 서버, API 키는 없습니다.

## 아이폰에 설치

이 프로젝트는 아이폰에서 YouTube나 Instagram 앱을 막지 못합니다. iOS는 다른 앱의 화면을 접근성으로 가로채는 기능을 이 앱에 열어 주지 않고, 홈 화면에 추가한 웹 앱도 다른 앱을 차단하지 못합니다. App Store용 앱이나 IPA는 만들지 않습니다. Apple 개발자 계정이 없고, 이 리눅스 환경에서는 아이폰에 사이드로드할 서명된 앱을 만들 수 없습니다.

아이폰에서 되는 것은 연습용 웹 앱뿐입니다. Safari로 연 페이지를 홈 화면에 추가하면 앱처럼 전체 화면으로 열리고, 한 번 받은 뒤에는 네트워크가 없어도 연습 흐름은 동작합니다. 실제 Shorts·Reels 앱은 그대로 열립니다.

임시 공개 주소는 더 이상 없습니다. 홈 화면 추가는 컴퓨터에서 이 저장소를 실행한 주소에 Safari로 접속할 수 있을 때만 됩니다.

1. 아래 **컴퓨터에서 실행**대로 정적 서버를 띄웁니다.
2. 아이폰 **Safari**에서 그 주소를 엽니다. 같은 네트워크라면 `http://컴퓨터IP:47231` 입니다. 페이지가 다 열릴 때까지 기다린 뒤, 아래쪽 **공유** 버튼(네모와 위쪽 화살표)을 누릅니다.
3. **홈 화면에 추가**를 고르고, 오른쪽 위의 **추가**를 누릅니다.
4. 홈 화면의 **한박자** 아이콘으로 엽니다. Safari 주소창 없이 열리면 설치가 된 것입니다.
5. 그 다음부터는 비행기 모드에서도 홈, 통계, 설정, 쇼츠 열기가 됩니다.

Chrome 등 다른 브라우저의 바로가기는 이 독립 실행 화면이 되지 않습니다. Safari를 쓰세요.

## 안드로이드에 설치

디버그 APK입니다. Play 스토어용이 아니라, 휴대폰에 직접 설치하는 파일입니다.

- 받는 주소: https://github.com/sonmj1418-hub/hanbakja/releases/download/v0.2.0/hanbakja-debug.apk
- 파일 위치: `release/hanbakja-debug.apk`
- 크기: 8,842,169바이트 (약 8.5MB)
- 패키지 이름: `app.hanbakja.shorts`

1. 휴대폰 브라우저에서 위 APK 주소를 엽니다.
2. 다운로드가 끝나면 알림이나 다운로드 목록에서 파일을 엽니다.
3. **출처를 알 수 없는 앱** 설치를 허용하라는 안내가 나오면, 이 브라우저에 대해 허용합니다.
4. 설치 후 홈 화면의 **한박자**로 엽니다.
5. 실제 쇼츠와 릴스를 막으려면 접근성을 켭니다.
   - 안드로이드 13 이상이면 먼저 **설정 → 앱 → 한박자 → 오른쪽 위 ⋮ → 제한된 설정 허용**이 필요할 수 있습니다.
   - **설정 → 접근성**으로 이동합니다. 한박자가 바로 없으면 **설치된 앱** 또는 **다운로드한 앱**을 엽니다.
   - **한박자**를 켜고 확인 창에서 허용을 누릅니다. 앱 안의 **접근성 설정 열기** 버튼도 같은 설정 화면으로 갑니다.

접근성을 켠 뒤 YouTube Shorts 또는 Instagram Reels 화면이 열리면 한박자의 이유 질문과 Level 1~3이 나타납니다. 나가기, 강제 종료, 시간 차단을 고르면 그 화면에서 뒤로 나와 한박자 홈으로 돌아옵니다. 시청을 고르면 그 화면으로 잠시 돌아가고, 그 화면에 머무는 동안만 사용 시간이 쌓입니다. 다른 앱, 메시지, 비밀번호, 계정, 화면 글은 저장하거나 보내지 않습니다. YouTube의 일반 재생 화면과 Instagram 스토리는 대상으로 삼지 않습니다.

## 컴퓨터에서 실행

```bash
npm install
npm run icons
npm run build
npm run serve:static
```

정적 서버는 `http://127.0.0.1:47231` 입니다. 개발 중 화면을 고칠 때는 `npm run dev`를 씁니다.

로직 확인:

```bash
node --experimental-strip-types --test lib/logic.test.ts
```

APK를 다시 만들려면 Android SDK가 필요합니다. SDK를 둔 뒤:

```bash
npm run build
npx cap sync android
cd android && ./gradlew assembleDebug
```

결과 파일은 `android/app/build/outputs/apk/debug/app-debug.apk` 입니다.

## 쓰는 법

1. 홈에서 오늘 누적 시간과 현재 Level을 확인합니다.
2. **쇼츠 열기**를 누르면 개입 화면이 나옵니다. 모든 단계에서 **나가기**가 됩니다.
3. Level 1은 이유를 고른 뒤 5초를 기다린 다음에야 피드를 엽니다.
4. Level 2는 물 마시기, 스트레칭, 독서, 걷기, 눈 쉬기, 호흡 중 하나를 제안합니다. 한 뒤에도 볼지 고르고, 그 결과를 기록합니다.
5. Level 3는 경고 후 이번 시청을 강제 종료하거나 10분, 20분, 30분, 1시간 동안 다시 열지 못하게 합니다.
6. 통계에서 일별 사용 시간, 실행 횟수, 개입, 이유, 재실행, 차단을 봅니다.
7. 설정한 시각이 지나면 리포트 화면이 하루 요약을 보여 줍니다. 브라우저 알림을 허용하고 앱이 열려 있으면 같은 내용을 알림으로도 보냅니다.

기본 기준은 누적 10분 미만 Level 1, 20분 미만 Level 2, 20분 이상 Level 3입니다. 설정에서 바꿀 수 있습니다.

시연할 때는 설정에서 시간 가속을 60배로 두세요. 실제 1초가 사용 시간 1분으로 쌓이고, 10분 차단은 실제 10초입니다. 가속이 1배일 때는 차단 시간도 실제 분입니다.

## 계획서 대비

구현한 것:

- 안드로이드 접근성으로 YouTube Shorts와 Instagram Reels 플레이어 화면을 구분하고, 같은 개입을 연 뒤 나가기·차단 시 그 화면에서 뒤로 이동
- Shorts 진입으로 간주되는 순간 개입 화면. 브라우저와 아이폰의 **쇼츠 열기**는 연습용 피드
- 실행 이유 6가지와 나가기
- Level 1 대기, Level 2 대체행동과 재실행 여부, Level 3 경고·강제 종료·시간 차단
- 당일 누적 시간으로 Level 결정
- 사용 기록과 개입 기록 (질문, Level, 대체행동, 수행 여부, 재실행, 차단 여부, 차단 시간)
- 일별 통계, 최근 7일, 일일 리포트
- 기준 시간과 알림 시각 설정
- 기록이 없을 때, 불러오는 중, 저장 실패, 손상된 기록 상태

이 프로젝트에서 하지 않는 것:

- 아이폰에서 YouTube·Instagram 앱을 막는 일. iOS 스크린 타임, 시스템 VPN, IPA, App Store 빌드는 없습니다. 홈 화면 웹 앱은 연습 흐름만 됩니다.
- YouTube나 Instagram 프로세스를 강제로 종료하는 일. 안드로이드에서 멈추면 뒤로 이동한 뒤 한박자 홈으로 돌아옵니다.
- 다른 앱의 사용량 API로 실행 시간을 읽는 일. 사용 시간은 쇼츠·릴스 화면에 머문 초만 이 기기에 더합니다.
- 화면 글, 메시지, 비밀번호, 계정을 읽어서 저장하거나 보내는 일.
- Room 데이터베이스. 같은 항목을 기기 로컬 저장소에 둡니다.
- WorkManager처럼 앱이 꺼진 뒤에도 저녁에 알림을 보장하는 일. 탭이 열려 있을 때의 브라우저 알림과 앱 안 리포트로 대신합니다.

TikTok은 넣지 않았습니다. 주간·월간 분석과 AI 추천도 범위 밖입니다. YouTube와 Instagram이 화면 구성을 바꾸면 쇼츠·릴스 구분이 잠깐 어긋날 수 있습니다.

5분 독서는 이름 그대로 대체행동 목록에 있습니다. 브라우저에서 바로 따라 할 수 있게 안내 타이머는 1분입니다.
