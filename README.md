# 한박자

YouTube Shorts를 열기 전에 한 박자 멈추고, 오늘 얼마나 봤는지에 따라 개입의 세기를 바꾸는 사용 조절 앱입니다.

캡스톤 계획서의 흐름인 **감지 → 이유 질문 → Level 1~3 개입 → 결과 기록 → 통계와 일일 리포트**를 브라우저에서 끝까지 사용할 수 있게 만들었습니다. 실제 YouTube 앱을 가로채지는 않습니다. 홈의 **쇼츠 열기**가 Shorts에 들어가려는 순간이고, 그 다음 피드는 사용 시간을 재기 위한 시뮬레이션입니다.

## 실행

```bash
npm install
npm run dev
```

개발 서버는 `http://127.0.0.1:47231` 입니다. 같은 네트워크의 휴대폰에서는 컴퓨터의 주소와 `47231` 포트로 열 수 있습니다.

기록은 이 브라우저의 `localStorage`에만 남습니다. 계정, 서버, API 키는 없습니다.

로직 확인:

```bash
node --experimental-strip-types --test lib/logic.test.ts
```

## 쓰는 법

1. 홈에서 오늘 누적 시간과 현재 Level을 확인합니다.
2. **쇼츠 열기**를 누르면 개입 화면이 나옵니다. 모든 단계에서 **나가기**가 됩니다.
3. Level 1은 이유를 고른 뒤 5초를 기다린 다음에야 피드를 엽니다.
4. Level 2는 물 마시기, 스트레칭, 독서, 걷기, 눈 쉬기, 호흡 중 하나를 제안합니다. 한 뒤에도 볼지 고르고, 그 결과를 기록합니다.
5. Level 3는 경고 후 이번 시청을 강제 종료하거나 10분, 20분, 30분, 1시간 동안 다시 열지 못하게 합니다.
6. 통계에서 일별 사용 시간, 실행 횟수, 개입, 이유, 재실행, 차단을 봅니다.
7. 설정한 시각이 지나면 리포트 화면이 하루 요약을 보여 줍니다. 브라우저 알림을 허용하고 앱이 열려 있으면 같은 내용을 알림으로도 보냅니다.

기본 기준은 누적 10분 미만 Level 1, 20분 미만 Level 2, 20분 이상 Level 3입니다. 설정에서 바꿀 수 있습니다.

시연할 때는 설정에서 시간 가속을 60배로 두세요. 실제 1초가 사용 시간 1분으로 쌓이고, 10분 차단은 실제 10초입니다. 가속이 1배일 때는 차단 시간도 실제 분입니다.

## 계획서 대비

구현한 것:

- Shorts 진입으로 간주되는 순간 개입 화면
- 실행 이유 6가지와 나가기
- Level 1 대기, Level 2 대체행동과 재실행 여부, Level 3 경고·강제 종료·시간 차단
- 당일 누적 시간으로 Level 결정
- 사용 기록과 개입 기록 (질문, Level, 대체행동, 수행 여부, 재실행, 차단 여부, 차단 시간)
- 일별 통계, 최근 7일, 일일 리포트
- 기준 시간과 알림 시각 설정
- 기록이 없을 때, 불러오는 중, 저장 실패, 손상된 기록 상태

브라우저만으로는 만들 수 없는 것:

- Android 접근성 서비스로 실제 YouTube 앱의 Shorts 화면을 감지하는 일
- Android 사용량 API로 다른 앱의 실행 시간을 읽는 일
- YouTube 프로세스를 실제로 강제 종료하는 일. 여기서의 강제 종료는 이번 시청을 끝내고 홈으로 돌아가는 동작입니다.
- Room 데이터베이스. 같은 항목을 브라우저 로컬 저장소에 둡니다.
- WorkManager처럼 앱이 꺼진 뒤에도 저녁에 알림을 보장하는 일. 탭이 열려 있을 때의 브라우저 알림과 앱 안 리포트로 대신합니다.
- iOS 스크린 타임이나 시스템 VPN으로 다른 앱을 막는 일

계획서에서 1차 범위가 아니었던 Instagram Reels와 TikTok은 넣지 않았습니다. 주간·월간 분석과 AI 추천도 범위 밖입니다.

5분 독서는 이름 그대로 대체행동 목록에 있습니다. 브라우저에서 바로 따라 할 수 있게 안내 타이머는 1분입니다.
